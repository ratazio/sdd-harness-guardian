# Evidence: T-003 — conditional accessible tab mechanics

**Builder:** Codex / implementation builder  
**Date:** 2026-08-27  
**Status:** approved — evaluate_t003_013, 2026-08-27

## Delivered increment

The v2 Human Visibility validator now activates the tab contract only when
rendered markup declares a `[role="tablist"]`. It keeps each tablist isolated:
every contained tab must have a non-empty ID, reference a rendered
`role="tabpanel"` through `aria-controls`, and receive the reciprocal
`aria-labelledby` value. Each group must have exactly one selected tab, with
the selected tab at `tabindex="0"` and all other tabs at `tabindex="-1"`.

`BriefParser` also records only rendered `<script>` bodies. The static oracle
requires click and keydown listener evidence; ArrowLeft, ArrowRight, Home,
End, Enter and Space; selection and active-panel mutation; focus; and
hash/history mutation. Visible prose, styles and templates cannot satisfy
that evidence. This is a bounded static proof, not execution or assistive
technology conformance.

The canonical v2 scaffold now declares its initial roving `tabindex` state.
Its native fragment anchors, source-ordered panels, print expansion and
reduced-motion CSS remain unchanged.

## Focused controls

`scripts/test_validate_human_visibility.py` now covers:

- a complete single tablist and two isolated complete tablists;
- click-only script and visible-prose-only token negatives;
- multiple selected tabs, broken tab/panel reciprocity, and an invalid second
  tablist that cannot borrow the first group’s selection;
- a v2 document without a tablist, which has no tab-contract obligation;
- the canonical scaffold itself, including native `href` anchors, `@media
  print`, and `prefers-reduced-motion:reduce` fallback tokens.

Diagnostics expose rule/category and tablist ordinal only; they never include
the fixture’s visible body or source payload.

## Correction after evaluator feedback

The initial implementation proved handler tokens anywhere in a rendered script
body. That was insufficient: comments or `if (false) { ... }` could present
dead token evidence, and one global handler could not prove that every
tablist is initialized independently.

The revised static grammar now accepts a live initializer with an arbitrary
function name and tablist parameter only when the script also directly applies
that initializer to `document.querySelectorAll('[role="tablist"]`). Inside the
initializer, the tab collection must be queried from that parameter. It keeps
the check structural and bounded: it does not execute JavaScript or prescribe
how many tabs, panels, architecture views, or content blocks a brief must use.

New focused regressions prove that:

- a copied complete handler in a block comment is not evidence;
- a copied complete handler below `if (false)` is not evidence;
- a document-wide tab query cannot satisfy the per-tablist association; and
- three independent tablists pass through the same initializer, demonstrating
  that there is no fixed eight-tab assumption.

The canonical template was changed from a document-wide, `tabs.length===8`
initializer to `initializeTablist(tablist)` plus a per-tablist bootstrap. Its
native anchors, no-script/source-order fallback, print expansion and
reduced-motion CSS remain present.

## Follow-up correction: scoped listener ownership

The preceding grammar still allowed a narrow false proof: a tablist-scoped
`tabs.forEach(...)` could be present but do no listener work, while a listener
attached only to a particular control elsewhere in the initializer supplied
the global `click`/`keydown` tokens. That does not prove that every tab in an
arbitrary group receives the handlers.

The validator now discovers collections queried from the initializer's own
tablist and accepts click/keydown evidence only when it is attached to the
callback parameter of that collection's `forEach`, or to a local named helper
explicitly called with that parameter. This remains intentionally bounded:
ordinary declarations, block-bodied arrow helpers and expression callbacks
are sufficient static forms; it does not impose a tab count, a panel layout,
or a named architecture/content scheme.

The evaluator fixture retains the valid scoped collection and all selection,
history, focus and keyboard tokens, but makes its `tabs.forEach` callback a
no-op and attaches both listeners only to `#tab-scope`. It now fails with the
missing scoped click and keydown listener diagnostics. The existing one-,
two- and three-tablist positive controls continue to pass.

## Limits and next gate

The validator deliberately does not execute the brief script, inspect browser
focus at runtime, or claim screen-reader conformance. Native anchors and
source order remain the no-script path; print/reduced-motion preservation is
structurally checked in the canonical scaffold. A distinct evaluator must now
review this implementation and the fixture realism before T-003 can move to
`approved`/`done`.
