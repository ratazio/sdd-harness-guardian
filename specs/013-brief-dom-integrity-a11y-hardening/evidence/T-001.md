# Evidence: T-001 — rendered parser and static-tab fixture contract

**Builder:** Codex / implementation builder  
**Date:** 2026-08-27  
**Status:** approved

## Decision and bounded contract

The implementation will retain Python's local `HTMLParser`, but its captured
DOM facts must be restricted to rendered markup. `script`, `style` and
`template` subtrees are inert: their descendants and literal IDs never enter
the rendered-node/duplicate-ID inventory, and their literal `</html>` text
never establishes a document boundary.

The parser may record one final rendered `</html>` event. After that event,
only whitespace data and comments are permitted. A rendered start tag, end
tag, declaration, processing instruction, or non-whitespace data is a tail violation. This is a
structural document rule, not a browser parse-recovery claim.

For v2 only, the tab oracle activates per rendered `[role="tablist"]`. Every
tablist must have an isolated reciprocal unique tab/panel set, exactly one
selected tab and its own roving tabindex state; a second tablist cannot borrow
the first one's selected tab or panels. Static handler evidence is collected
only from rendered `<script>` bodies, never from visible prose: it requires a
click listener, `keydown` listener, all Arrow/Home/End/Enter/Space key
branches, selection mutation, active-panel mutation, focus and hash/history
mutation. Source text is evidence of maintained behavior, never a claim that
the validator executes JavaScript or certifies assistive-technology use.

## Probe and current baseline

Command run:

```text
python -c '<HTMLParser event probe with template, script literal </html>, comment and rendered tail>'
python scripts/test_validate_human_visibility.py
```

Observed parser order: the template child arrives as start/end events, the
script literal `</html>` arrives as data, the rendered `</html>` arrives as
an end event, a trailing comment is separately identifiable, and the trailing
`div` arrives as rendered start/data/end events. The existing focused suite
returned `RESULT: PASS` before production changes.

## Rejected alternatives and limitations

- Full-source regex cannot reliably distinguish inert markup or comments.
- Browser execution would exceed the deterministic/offline scope and still
  would not replace independent accessibility review.
- The checks do not score prose, layout, runtime behavior or assistive
  technology compatibility.

## Evaluation correction

The first independent review correctly rejected a global token search because
visible prose can contain every key name while a tablist remains click-only.
The contract and fixture matrix were amended to scope handler evidence to
rendered script bodies, add the prose-token negative, add declaration and
processing-instruction tail negatives, and require isolated validity for each
tablist. After this amendment, `python scripts/test_validate_human_visibility.py`,
`python -m py_compile scripts/validate_human_visibility.py`, and `git diff
--check` passed (the last command emitted only an unrelated CRLF warning for
`specs/INDEX.md`).
