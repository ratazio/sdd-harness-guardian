Decision brief

SPEC 029 replaced agent-authored brief HTML with a projected content model, and the honest record is that it took a real locator-collision fix, a real doctrine gap in the agent that runs the review chain, an owner-redefined success metric, and a cumulative line count that still reads as additive on its face.

Guardian maintainers and the owner decide whether the three gates suspended by D-007/D-011/D-012 — human_visibility_ready, brief_coverage_ready and tasks_ready — can be set true for SPEC 029 itself, closing the bootstrap this initiative exists to prove.

Value & scope

The bundle accumulated eight correction cycles over the same stakeholder-brief pipeline between releases 0.1.2 and 0.4.0, with two structural defects: agents author HTML by hand at a cost of three full-context passes per brief, and the doctrine that governs that authoring contradicts itself across eight-plus files. SPEC 029 treats the cause — an agent authoring markup from dispersed doctrine — instead of adding another orchestration layer on top.

spec.md · 1. Problema — “oito ciclos de correção sobre a mesma”

NG-008 names the boundary this very brief operates under: the dispensation that let SPEC 029 skip the old brief pipeline while it built the new one is scoped to this initiative only, suspends only the ORDERING of human_visibility_ready (never its existence), and expires with this SPEC. Every other protected invariant — distinct identities, evidence before done, independent review, rendering does not equal approval, HTML is not a source — stays fully in force (D-008).

tasks.md · Task ledger — “T-010 | pending | Brief da própria 029 pela esteira nova e liberação dos gates”

T-002's first review cycle did not pass. `resolve_locator` accepted a partial substring match in either direction on normalized text, so a model declaring `source_section: "Escopo"` against a source that only had "## Fora de escopo" resolved silently to the opposite-meaning heading instead of refusing. On the not_applicable coverage path, that resolved locator becomes the displayed fragment — false provenance passing verification, exactly what FR-003/O-002 exist to prevent. The fix requires an exact normalized match first, with one narrow digit-bearing-ID prefix exception guarded by content (not length), and refuses on any ambiguous collision between distinct headings. This is not a hypothetical: the same guard fired for real during T-009's matrix run, on a genuine duplicate "T-002" heading in one mock's tasks.md.

tasks.md · Implementation constraints — “Reversível por `git revert`. Só ocorre após T-001…T-007 aprovadas.”

Validation

Validation runs at three levels with an explicit boundary between them, because confusing the first two with the third is a recurring defect in this repository: deterministic pytest proves structure, provenance, lifecycle and invariant preservation, and never quality; static comparison measures already-versioned artifacts at zero cost; independent qualitative review over HTML served in loopback is the only thing that judges whether a brief is fit to decide from. A deterministic PASS is never reported as experience approval.

validation-plan.md · 1. Strategy — “Um PASS determinístico não pode ser reportado como aprovação de experiência.”

M-001, M-002, M-005, M-006, M-007, M-0081 attempt to a passing model+projection each
M-0032 attempts — a scope fragment was transcribed without the bold marker separating it from the surrounding source text
M-0042 attempts — an impact fragment was copied from the wrong mock's impact-map.md by mistake
Total10 attempts across 8 mocks, median 1, max 2, against 6/9/15 full pipeline runs in the historical record

Both multi-attempt failures were `project_brief.py` correctly refusing with "fragment ... does not occur literally in source", naming the offending block — exactly the FR-003 failure mode working as designed, and both were human/agent transcription errors, not defects in the model or the mechanism. The comparison against the historical 6/9/15 execution counts is honest about not being the same unit: those numbers count full old-pipeline rounds (HTML authoring + two reviews each); these ten count YAML edit-and-reproject cycles, because there is no HTML to re-author under the new pipeline.

decision-log.md · Decision Log: 029-brief-content-model-and-doctrine-consolidation — “Record decisions that change scope, architecture, validation, risk, precedence”

D-033 is the most consequential decision in this route: faced with T-008's own -778-line removal against the SPEC's +3,826-line cumulative diff, the owner ruled that R-006/IR-006's real criterion is not static line count but recurring operational cost per brief — convergence and rework over time — and that one-time investment code (schema, projector, deterministic checks) is acceptable when it lowers that recurring cost, which is what AC-009c/AC-009d actually measure. This is a genuine mid-flight redefinition of what "done" means for R-006, made by the owner, not smoothed over by a builder choosing the friendlier reading.

D-034 is the owner's qualitative approval of M-006 and M-007 under AC-009c: M-007's prose-only coverage route is accepted because its source genuinely has no table, and M-006's inherited generic per-surface impact content is accepted specifically because the model states the gap as visible text instead of hiding or inventing detail — the exact posture EC-005/NG-001 require when a source is weak.
