## Delivered increment

`scripts/architecture_visual_contract.py` introduces a deliberately narrow
contract for an authored v2 `#architecture` route that explicitly declares
`data-architecture-visual="material"`. It requires a source-backed topology,
named relations, all four text legend states, a unit-bearing surface map and a
supported or explicit N/A/discovery zoom. It leaves routes with no material
architecture (or an explicit reasoned non-material declaration) free from an
SVG requirement.

The contract is consumed both by `scripts/validate_human_visibility.py` and
by `scripts/validate_bundle.py`, which means a renderer promotion cannot call a
visually-material, text-only fallback structurally complete. The canonical
template now exposes only the corresponding styling primitives; it does not
mark its scaffold architecture as material.

## Regression evidence

- Positive source-backed fixture: topology SVG with named nodes and relation,
  `proposed`/`preserved`/`out-of-scope`/`discovery` legend, declared surface
  unit, and source-backed N/A zoom.
- Negative fixture: a route declaring material architecture but containing
  only a textual relation/fallback. It deterministically fails for missing
  topology, surface-map and zoom projections.
- Immaterial fixture: reasoned `not-material` route passes without SVG,
  preserving proportionality.

## Revision after independent REVISE

The first independent evaluation found that the original guard checked for
tokens anywhere in `#architecture`, so a loose SVG path, disconnected nodes or
empty legend could satisfy it. This was a contract defect, not a visual
judgment disagreement.

The repaired guard now retains the architecture-route tree and binds every
required primitive to its own projection. A topology must name two distinct
node IDs and include a relation whose `from`/`to` endpoints join those IDs.
Legend entries and the text equivalent must have visible non-empty text. SVG
requires `role="img"` and a non-empty accessible name; semantic HTML has the
same text-equivalent requirement. The new regressions reject the reviewer's
disconnected/empty SVG bypass and an empty semantic-HTML bypass.

## Second revision after independent REVISE

The second evaluation found that one valid relation still masked a second
relation that pointed from an unknown endpoint. The contract now uses the
exact `data-architecture-relation-from` and
`data-architecture-relation-to` attributes. Every declared relation must name
itself, carry a non-empty label, declare both endpoint attributes, reference
existing node IDs and connect two distinct IDs. A valid edge no longer permits
an additional missing or self-referential edge to pass.

The evaluator first returned two real structural bypasses (loose/empty

builder repaired both and the evaluator independently approved the exact hashes

## Limitations and evaluator focus

This is a structural guard, not a visual-quality or source-semantic verdict.
It cannot decide whether labels are readable in a rendered viewport, whether a
source fact is semantically sufficient, or whether a composition is C-level
ready. Each generated material brief still needs independent render review.
