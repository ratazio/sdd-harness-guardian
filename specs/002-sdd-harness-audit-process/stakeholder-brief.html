002-sdd-harness-audit-process

Create a reusable audit process for judging whether a repository has a real SDD and Harness Engineering operating model, including graph reachability, evidence-backed findings and a stable HTML report.

Decision Snapshot

OutcomeMaintainers can request a deep audit of SDD/harness maturity.
IncrementAudit skill, agents, rule, workflow, report template, framework docs and manifest wiring.
StatusImplemented; awaiting independent evaluation.

What Changes

The Guardian gains a first-class audit capability that checks SDD artifacts, harness graph reachability, agent/skill contracts, memory, validation, hard mirrors and process files that exist but are not actually usable.

Out Of Scope

No hosted UI, no product-code changes, no automatic consumer repository mutation and no script-only HTML report generator.

Validation

Bundle validator and scaffolder smoke must pass. A distinct evaluator must review the evidence before the task can be marked done.
